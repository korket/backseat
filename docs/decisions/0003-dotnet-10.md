# ADR 0003: Use .NET 10 for the initial Backseat implementation

Status: Accepted

## Context

Backseat is Windows-first and needs a maintainable host for process management, Windows interop, long-running asynchronous sessions, CLI tooling, and future backend adapters.

The project also benefits from a strongly typed core because action and observation contracts are safety-relevant.

## Decision

Use .NET 10 for the initial Backseat implementation.

Repository scripts may treat the .NET 10 SDK as a required development dependency once implementation work begins.

## Alternatives considered

- Rust for the complete application.
- Python as the primary runtime.
- TypeScript/Node.js as the primary runtime.
- Postpone the implementation-language decision.

## Consequences

### Positive

- Strong Windows and process interoperability.
- Good async and CLI ecosystem.
- Typed contracts for session/action/receipt models.
- Straightforward testing and packaging for a Windows-first tool.

### Negative

- Adds a runtime/toolchain dependency.
- Native Windows edge cases may still require P/Invoke, Rust, or another native helper.
- The choice may need revisiting if backend constraints strongly favor another language.

## Revisit when

A demonstrated backend or platform requirement makes .NET a material obstacle rather than a preference.
